**Result:** 56 findings, 53 of them confirmed by at least two of three checkers, plus 3 from the last reader that were not put to the checkers. 24 are in the serious group. 107 things were checked and found right (19.4). 79 points could not be judged by reading alone (19.5).

## 19.1 In plain words

The structure is sound: one acting function, one provider, the encrypted memory, the limits. No finding says the design is wrong. The serious findings are holes at the edges, and most are small to close. The ones that matter most to you:

1. **A note whose title starts with "-e" could run a command on your Mac (R4).** The title is handed to the Mac's script runner in a way that lets it be read as an option. A misleading page could ask him to make such a note. Minutes to fix. The worst finding of the review.
2. **Apps on your "Never read" list still appear in the picture (R1).** When the mouse is outside the front window he sends a picture of the whole display, and only Phew's own windows are left out of it. A password manager open beside your work is in that picture. Minutes to fix.
3. **The secrets filter has gaps (R2, R24, R3).** A field under the mouse has its name and its value filtered apart, so "Password" and the value next to it pass. Secrets written `LIKE_THIS=value` are missed. And pictures are not filtered at all, which was already known: that one takes days and is a design decision.
4. **Undo is not yet trustworthy (R5, R6, R16, R17).** A long note can be changed while he reports a timeout and offers no Undo. Undo forgets what it kept before the put-back succeeds. Undo writes over an edit you made after the job. An undone delete does not bring back everything (alarms, the folder).
5. **Money: two ways past the limits (R8, R9).** A call you stop is logged at almost no cost although it was paid, so the daily ceiling undercounts. A task's 50 cents is checked only between requests, and one request may use all its searches at once.
6. **Screen text reaches three agents without the "this is data" rule (R15, R18).** The agent that acts has the rule; the ones that explain, route and follow do not. Today the harm is a wrong answer. Once connections exist it becomes a way to make him act, so it must be closed before phase NB.
7. **Links on the card (R12).** A link in an answer or a report is clickable whatever it opens, and the text shown can hide where it goes.
8. **The shortcut (R11).** It also fires when a third key is held with the two, and a hold then opens the microphone.
9. **Sensitive projects (R10).** Past questions about a project marked sensitive stay in the normal memory file and in the export.
10. **The disk image is built with the debugger door open (R14).** Fine on your Mac; it must be closed before anyone else installs it.
11. **Your real addresses are in a tracked document (R23).** `docs/16-control.md` quoted the author addresses found in the history. Corrected in the commit that adds this page; the history itself still holds them, as already known, and must be rewritten before the repository is made public.
12. **Tests miss four important guards (R19 to R22, R13).** "Never read secure fields" and the secrets filter call have no test; the build test that keeps acting in one function can be slipped past in three ways; the stand-in used to test Undo hides the alarm loss.

**Also worth knowing, not serious:** the Observer, meant to be off, still runs on some windows and stalls the answer by 2 to 4 seconds (R-speed list); from the ninth reply of a conversation the cache is rewritten every time and never read, which costs money for nothing; every typed question waits for the small routing call before the answer can start.

#### R4. A note title that starts with "-e" becomes script code and can run any shell command

- **Where:** `Phew/Senses/Hand.swift:920` · reader: acting · fix size: minutes · 3 of 3 checkers could not knock it down
- **What is wrong:** osascript is started with the fixed script lines followed directly by the words (`process.arguments = source.split(...).flatMap { ["-e", ...] } + args`). osascript reads any leading argument that begins with a dash as one of its own options, so a first word of the form `-e<text>` is added to the script as another line. The comment on line 915 ("no word ever becomes script code") does not hold for the first argument. The one script whose first argument is a free word is `findNotes` (line 1073, `script(Self.findNotes, [title])`), used by rename_note, edit_note and delete_note.

(3)": the shell command inside the title ran. #### R5. A long note is changed or deleted, but Phew reports a timeout and offers no Undo

- **Where:** `Phew/Senses/Hand.swift:926` · reader: acting · fix size: hours · 3 of 3 checkers could not knock it down
- **What is wrong:** `osascript` waits in a loop for the process to end and reads its output only afterwards (lines 926 to 942). A pipe holds about 64 KB; when the script's answer is bigger, osascript blocks while writing and never ends, so Phew kills it after 60 seconds and returns `timeout` with empty output. `changeNote` makes the change first and returns the note's whole old body last (lines 1176 to 1195), so the change has already landed. `note()` then returns no kept value for any end but `done` (line 1082), so there is no Undo. The same loss happens when Stop or the 60 second limit cuts a script after Notes took the change.
- **A case:** edit_note on a note whose HTML body is over about 64 KB (a long text note, or one with a pasted picture). Notes replaces the body. osascript hangs on its output, the Hand lock is held for 60 seconds, the card says "The app did not answer in time. I stopped." The old body existed only in that unread output: it is gone, and the card has no Undo. With delete_note the note goes to Recently Deleted and the card says the same.
- **Fix:** Read both pipes while the process runs (a background `readDataToEndOfFile` per pipe, or `readabilityHandler`), then wait. Safer still: read the old body in one script, keep it, and change in a second script, so what is kept never depends on the change's output.
- Checker (reach): stands. Reachable by any edit_note, rename_note or delete_note on a note whose HTML body exceeds the pipe buffer: Hand.swift:926-930 waits for exit before the only read at 941, changeNote changes first and returns the old body last (Hand.swift:1177-1195), and Hand.swift:1082 returns no kept value on timeout, so TextCardActing.swift:65 sets no Undo. No debug flag or test seam is involved (HandChanges is built with the real osascript at Hand.swift:891). The size of a real note's body was not measured; a long text note is enough.
- Checker (truth): stands. Hand.swift:926-930 waits for the process to end before the first read at 941, so output above the pipe buffer blocks osascript until the 60 s cut returns (.timeout, ""). changeNote changes first and returns heldBody last (Hand.swift:1176-1195); note() returns no kept value unless end == .done (1082). No size cap exists and HandChangeTests use a fake script, so no test covers it. Not run live: a real note over 64 KB would settle the exact size.
- Checker (harm): stands. Could not knock down. Phew/Senses/Hand.swift:926-942 reads the pipe only after the process ends, and changeNote writes first and returns the whole old body last (Hand.swift:1190-1195), so a note body over the pipe size (any note with a pasted picture) is replaced, the old body is never read, Hand.swift:1082 returns no kept value, and the card says the app did not answer (Phew/Shell/ActJob.swift:170): real loss of the Undo copy plus a false report that invites a retry. For delete_note the harm is small (the note sits in Recently Deleted).

#### R6. Undo throws away what it kept before the put-back succeeds

- **Where:** `Phew/Senses/Hand.swift:543` · reader: acting · fix size: hours · 3 of 3 checkers could not knock it down
- **What is wrong:** `undo` takes all kept values out of the job first (`job.takeKept()`), and the card clears `undoJob` before starting (TextCardActing.swift:90). Each put-back then goes through `act` in a new job, so the off switch, secure input and the per-minute ceiling apply (lines 512 to 515). The loop stops at the first end that is not `done` (`where end == .done`) and the rest is dropped. Nothing is kept for a second try.
- **A case:** A job renames 25 reminders and ends. The user presses Undo. The per-minute ceiling is 20 (`perMinute`), and the job's own actions of the last minute count too, so Undo stops with `minuteCeiling` after at most 20 put-backs, often after none. The remaining old titles lived only in memory and are gone; the button is gone too. The same happens when a password field has the keyboard anywhere on the Mac (`secureInput`), when a script times out, or when macOS refuses access: one failed Undo loses every old value.
- **Fix:** Keep the values until each put-back ends `done`: on failure put the unrestored ones back on the job and leave the Undo button. Let a restore skip the per-minute ceiling (it only puts back what Phew changed), as `back` already skips it.
- Checker (reach): stands. Reachable from the card's Undo button (TextCard.swift:733, TextCardActing.swift:88-93): Hand.swift:543 empties the kept values first, each put-back goes through act and the shared per-minute counter (Hand.swift:515, 520, 434), and the loop at Hand.swift:546 stops at the first end that is not done. A job with more than 20 changes always hits minuteCeiling on Undo; fewer suffice when the job's own actions fall in the same minute. secureInput at Hand.swift:512 fails it too.
- Checker (truth): stands. Hand.swift:543 empties the job's kept values first, the loop at 546 stops at the first non-done end, and nothing puts the rest back; TextCardActing.swift:90-91 clears undoJob and canUndo before the result. Each restore passes script() gates at Hand.swift:512-515 (secure input, shared `recent` per-minute count of 20). HandChangeTests.swift:271-277 only asserts Undo returns .off and never checks a second try is possible.
- Checker (harm): stands. Could not knock down. Phew/Senses/Hand.swift:543 empties the kept values first and Phew/Shell/TextCardActing.swift:90 clears undoJob, then each put-back passes brake (Hand.swift:515) against the shared `recent` list with perMinute = 20 (Hand.swift:359); put-backs run with no model wait, so a job with about a dozen or more changes in its last minute stops Undo part way and the rest of the old values are gone, leaving items half restored. Not recorded as a known limit in docs/07-decisions.md:207.
