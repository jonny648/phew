PHEW · DEVELOPER REVIEW · 17 NOVEMBER 2026 · VERSION 0.2.1

The code review

Every file of the app was read by eight reviewers, one per area. Three checkers then tried to prove each finding wrong. This page says what was found, in plain words, and what is already fixed.

56findings, 3 more from a last pass
24serious: security, privacy, lost data or money
37fixed in the code on 16 November
107points checked and found right

Not installed yet. The fixes are in the code. The app on your Mac is still 0.2.1, with the hole described under R4. Say "install" to get 0.2.2.

The short version

The structure is sound: one function that acts, one way to the model, an encrypted memory, limits on money. No finding says the design is wrong. The serious ones are holes at the edges, and most were small to close.

  • The worst (R4): a note whose title starts with "-e" could run a command on your Mac. Closed.
  • Privacy: apps on your Never-read list, password managers and terminals were still in the whole-screen picture and in the watch during a guide. Closed. A field's name and its value were filtered apart. Closed.
  • Undo could forget what it kept, write over your later edit, or bring a deleted item back incomplete. Fixed, with limits said on the card.
  • Money: a stopped call was logged at almost nothing; one request could pass a task's cap. Fixed; a task can now pass its cap by at most a fifth.
  • Text on the screen now reaches every agent marked as data, never as orders. This had to be closed before connections are built.
  • Still yours to decide (R3): pictures are not passed through the secrets filter. What is visible on screen is in the picture.

A second check on the fixes themselves found three more faults (the screen watch, a weaker data block in two agents, money already spent not counted). All three were fixed the same day. 531 tests pass, 0 fail, 6 are live-only and were not run.

The serious findings

R1fixed 16 Nov3 of 3 checkers

Whole-screen picture includes apps on the Never read list and password managers

When the mouse is not inside the front window, Phew sends a picture of the whole display. That picture leaves out only Phew's own windows. Every other visible window is in it, including apps the user put on "Never read this app", password managers and terminals. The PNG goes to the Claude API (Guide, Doer, Follower, Runner).

Phew/Senses/ScreenCapture.swift:41 · fix size: minutes

R2fixed 16 Nov3 of 3 checkers

Field under the mouse: its name and its value are filtered apart, so a visible password or token is sent

The secrets filter removes a value only when it follows a password word ("password", "PIN", "token", "api key"...). For the element under the mouse, the label and the value are cleaned as two separate strings (lines 66-67), so the filter never sees them together. `Guide.context` then joins them into one line (`Guide.swift:216-217`) and nothing filters that line again. The Doer uses the same line.

Phew/Senses/ContextPacket.swift:66 · fix size: minutes

R3your decision 493 of 3 checkers

The picture is never filtered: a key or card number visible on screen leaves the Mac

The rule says the secrets filter runs before any network call. It runs on text only. The screenshot is attached as taken (`ClaudeProvider.swift:75-78`). The code says so itself in a shortcut note on this line. This is a bent privacy rule that the code does not make up for anywhere.

R4fixed 16 Nov3 of 3 checkers

A note title that starts with "-e" becomes script code and can run any shell command

osascript is started with the fixed script lines followed directly by the words (`process.arguments = source.split(...).flatMap { ["-e", ...] } + args`). osascript reads any leading argument that begins with a dash as one of its own options, so a first word of the form `-e<text>` is added to the script as another line. The comment on line 915 ("no word ever becomes script code") does not hold for the first argument. The one script whose first argument is a free word is `findNotes` (line 1073, `script(Self.findNotes, [title])`), used by rename_note, edit_note and delete_note.

Phew/Senses/Hand.swift:920 · fix size: minutes

R5fixed 16 Nov3 of 3 checkers

A long note is changed or deleted, but Phew reports a timeout and offers no Undo

`osascript` waits in a loop for the process to end and reads its output only afterwards (lines 926 to 942). A pipe holds about 64 KB; when the script's answer is bigger, osascript blocks while writing and never ends, so Phew kills it after 60 seconds and returns `timeout` with empty output. `changeNote` makes the change first and returns the note's whole old body last (lines 1176 to 1195), so the change has already landed. `note()` then returns no kept value for any end but `done` (line 1082), so there is no Undo. The same loss happens when Stop or the 60 second limit cuts a script after Notes took the change.

Phew/Senses/Hand.swift:926 · fix size: hours

R6fixed 16 Nov3 of 3 checkers

Undo throws away what it kept before the put-back succeeds

`undo` takes all kept values out of the job first (`job.takeKept()`), and the card clears `undoJob` before starting (TextCardActing.swift:90). Each put-back then goes through `act` in a new job, so the off switch, secure input and the per-minute ceiling apply (lines 512 to 515). The loop stops at the first end that is not `done` (`where end == .done`) and the rest is dropped. Nothing is kept for a second try.

Phew/Senses/Hand.swift:543 · fix size: hours

R7fixed 16 Nov3 of 3 checkers

The paying word list misses common order buttons, so the code lets them through

The rule says Phew's code, never the model, refuses paying. The code refuses only when the control's name, its menu path or the window title holds one of the listed whole words. Buttons such as "Confirm order", "Order now", "Complete order", "Place your order" (the list has only "place order"), "Donate", "Send money", "Conferma ordine", "Ordina ora", "Invia denaro", "Bonifico" hold none. `finalWords` (line 68) misses them as well, so the card does not even tag the step.

Phew/Senses/NeverList.swift:27 · fix size: hours

R8fixed 16 Nov3 of 3 checkers

A cancelled model call is logged at almost zero cost, so the daily ceiling and the task cost undercount

When a call is cancelled (Stop, card closed, the Follower's 3.5 s cap, the Runner's 300 s cap), the log line uses `parser.usage`. At that moment the parser holds only the numbers of `message_start`: the input tokens of the first step and about one output token. The output tokens, the later sampling steps and the web searches arrive only in the final `message_delta` (SSEParser.swift:56-58), which a cancelled stream never reads. Anthropic still bills what was generated. `Spend`, the daily ceiling, the task reserve and the cost shown for a task all come from these lines.

Phew/Brain/ClaudeProvider.swift:45 · fix size: hours

R9fixed 16 Nov3 of 3 checkers

A task's 50-cent cap is checked only between requests, and one request may use the whole search and page budget

`spent >= limits.capUSD` runs after a round returns. Each request carries `max_uses` 5 searches and 8 page reads of 8000 tokens (Runner.swift:101, 108), and Anthropic runs these inside one request, one sampling step after another. Phew sees no usage until the request ends, so nothing stops a request that is already over the cap. The 80% rule (`writeAtUSD`, line 211) is also checked only after the round.

Phew/Brain/Runner.swift:190 · fix size: hours

R10fixed 16 Nov3 of 3 checkers

Past questions of a sensitive Project stay in the normal file and in the export

A past question is put under the second lock only when its `mentions` list holds a sensitive thing. Its `project` column is not looked at, in `add(_ event:)` (line 268) or in `moveSensitive` (lines 225-229). The write path sets `project` from code's own detection (MapWrite.swift:152) without adding it to `mentions`, and a Note about nothing is attached to that Project without a mention either (MapWrite.swift:352). Forget does treat `project` as belonging to the thing (MapWrite.swift:546), so the two rules disagree.

R11fixed 16 Nov3 of 3 checkers

The two-key shortcut also fires when a third key is pressed with it, and a hold then opens the microphone and sends the screen to Claude

`flags()` looks only at the modifier bits (`rawFlags & 0x50 == 0x50`). The key-down monitor installed while the chord is down (`watchEscape`, line 57-63) reacts to Escape (keyCode 53) only. So right Option + right Command used as part of any other app shortcut (for example right ⌥⌘ + C, or with Shift added) counts as Phew's shortcut.

R12fixed 16 Nov3 of 3 checkers

Links in an answer or report are clickable with any scheme, and the visible text hides the real destination

`AttributedString(markdown:)` turns `[text](url)` and `<scheme:...>` into link attributes for any URL scheme. `CardView.answerText` (TextCard.swift:661-666) draws it in a SwiftUI `Text`, and no `openURL` handler is set anywhere in the Shell (grep for `openURL`/`OpenURLAction` finds none), so a click goes to the system's default opener.

R14fixed 16 Nov3 of 3 checkers

The shipped disk image is built in a way that leaves the debugger door open

The script makes the installer with `xcodebuild ... -configuration Release ... build`, signed with the "Apple Development" identity (Phew.xcodeproj/project.pbxproj line 345). A plain `build` (not `archive`) with a development identity makes Xcode add the `com.apple.security.get-task-allow` entitlement to the signature, because CODE_SIGN_INJECT_BASE_ENTITLEMENTS is on by default and the project never turns it off. That entitlement cancels the main protection of the hardened runtime (line 351): other processes of the same user may attach to Phew and read its memory. Line 9 only runs `codesign --verify`, which does not look at entitlements.

Tools/make-dmg.sh:7 · fix size: minutes

R24fixed 16 Nov

Secrets filter misses secrets written with underscores (.env and JSON style)

The password rule starts with `\b(password|...|api key|secret key|access token|token)\b`. An underscore counts as a word character, so there is no word boundary between `_` and the word. The list also only knows `api key`, `secret key` and `access token` written with a space. Values with no known prefix (sk-, ghp_, AKIA...) are then caught by nothing. No reader looked at this file's patterns, and PhewTests/SecretsFilterTests.swift has no case with an underscore name (grep for _PASSWORD, API_KEY, _SECRET found none).
