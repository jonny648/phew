P5 Map

Order 1. Phew remembers your projects, on the Mac. Design in docs/05-map.md. Subagent: map, brain, senses, shell.

  • Done when: Unit tests create, read and search each table, and write and read one made-up thing of each of the eleven classes and one of each of the seven links. A search with a full sentence, a file name, an accented word typed without its accent or an empty question does not fail. SQLite on the Mac is version 3.42 or later, which a real delete needs.
  • Done when: Unit tests on made-up Librarian replies give the expected rows for each of the ten classes the Librarian can write and each of the six links it can write, never create a second Me, set the "understands" strength by Phew's own code from what the reply says about a Topic, reuse a thing only when name, class and Project all match, treat the same name in another class or Project as a new thing, and drop a class or link outside the list. A unit test shows the Librarian's request holds no window text, no picture and no list of elements. At least 8 of 10 made-up interactions run through the real Librarian give the expected writes. With a made-up bank balance and a private message on screen, both are in the Map marked sensitive, and a password on screen is not. Rows appear after a real question.
  • Done when: After quitting and reopening Phew, a second question on a topic uses the first. calls.log shows no extra model call for the recall. A unit test shows a made-up key stored in a fact is removed by the secrets filter before the request.
  • Done when: After quitting and reopening Phew, "What did I do last time on this project?" is answered from the Map. A question that needs more than the last 3 past questions, such as "What did I do on this project this month?", is answered in full, and calls.log shows the Guide searched the Map once for it, without the search words. A unit test shows a third search in one question is not made.
  • Done when: "And the second one?" is understood without repeating the question. A unit test shows the follow-up request carries the earlier question and answer as text and the fresh look only: no screen text and no picture from the earlier turn. A unit test shows at most 3 turns are kept, and all are dropped 5 minutes after the last answer and on Quit.
  • Done when: Right project named in 3 situations, and none named when nothing matches. After "this is the X project", the next call from the same file names X. The path or address reaches the packet through the secrets filter. The Map keeps only the app name, the title and the path as labels, never the screen text.
  • Done when: After quitting and reopening Phew, an answer uses a preference you told him before quitting, without being told again. A unit test shows the same facts give the same profile text, with no model call.
  • Done when: Unit tests on made-up facts pass. After a correction, the old fact can still be read as history, with its end date and the fact that replaced it. A weaker source never replaces a stronger one: it is kept beside it as an "unconfirmed" Note. After a forget, the thing, its past versions, its links, the Notes about it and the past questions that mention it are hidden from every read and from both search indexes, and Restore brings all of it back. After the real delete (30 days on a moved clock, or Delete now), past questions no longer mention it, things that were only linked to it stay, other facts keep their source, and the made-up name is not found in the database file or its write-ahead file read as raw text. In the running app: "Remember that X" is stored as told and the card says so in one line; one correction works; he says where he learned a fact; "forget that" acts at once, names what went, and the next profile and the export no longer show it.
  • Done when: Unit tests on made-up data for each of the eight terms, including a late Task that still counts as due soon, and for how the strength of "understands" moves. After two real questions on one topic, "What have I still not understood?" names that topic. After you tell him a task due in 3 days, "What is due this week?" names it.
  • Done when: File opens and matches the database, with sensitive facts left out unless you tick them. It is saved only where you choose, in the system folder window, and the front app is active again after it closes.
  • Done when: Unit tests on made-up data show recall hands the Guide the open point to start from, the next step, and "may be outdated" on a stale fact, with origin and date on every line. After you tell him a task due this week, "What should I do next?" names it. With two made-up facts of the same origin that disagree, he says so and asks.
  • Done when: No text sent to the model from Phew/Brain says "student" (Conductor, Observer, Guide, Follower and the self-check's test text), and the live self-check still passes, with the 10 routing samples of P3.5.

  • Done when: A colour change and a blur slider in Figma cause one look each. A scroll causes no look and the pointer stays on its target.
  • Done when: A click on empty space sends no model call. Seen in calls.log.

A look waits until the screen has stopped changing. The watch alone sends no model call, seen in calls.log. No frame or picture file is written to disk or to a log while it runs.

  • Sensitive facts open only after Touch ID or your password. Needs the data protection keychain and a provisioning profile. Sensitive facts are searchable only after you unlock them.
